# Contract: Theming stable class reference

**Feature**: `022-v151-fix-batch` | **Status**: normative (amends
[021 theme-blocks.md](../../021-site-redesign/contracts/theme-blocks.md) and
[site-theming guide](../../../docs/guides/site-theming.md))

## Stability commitment

The CSS class names and custom properties listed in `docs/guides/site-theming.md`
are the site's theming surface for 1.x. The build never validates them (no
diagnostic exists for classes; the `theme_invalid` diagnostic covers template
blocks only), so this document is the contract:

- Renaming a listed class or variable is a breaking theming change; it requires a
  changelog entry in the `### Fixed`/`### Changed` section naming the old and new
  names.
- Adding a class or variable is additive and needs only a changelog mention.
- An unlisted class carries no stability promise.

## What the guide gains

A "Stable classes, variables, and blocks" section in `docs/guides/site-theming.md`
that lists, in one table each:

1. **Layout classes** emitted by `layout.gohtml`: page shell (`site-header`,
   `site-main`, `footer`), brand (`brand`, `brand-link`), navigation
   (`nav`, `nav-tree`), theme toggle (`theme-toggle`), pager (`pager`), accent
   bar (`accent-bar`).
2. **Page content classes** emitted by `index.gohtml`, `element.gohtml`,
   `rail.gohtml`, `view.gohtml` and `partials.gohtml`: `landscape`, `systems`,
   `views`, `rows`, `row`, `row-body`, `row-head`, `row-desc`, `stats`,
   `element-list`, and the chip classes that `partials.gohtml` `chip` emits.
3. **Custom properties** already documented (`--bg`, `--card`, `--txt-1`…`--txt-3`,
   `--link`, `--accent`, `--kind-<kind>-bg`/`-fg`), kept as the colour surface.

The table is generated by reading the built-in templates (no runtime generation;
YAGNI per research R5). The final class list is filled from the templates at
implementation time; this contract fixes the section's presence, location and the
three-table shape, not each row — the guide is normative for the names.

## Relationship to theme_invalid

Template blocks and CSS classes are two halves of one theming contract:

| Surface | Protection |
|---|---|
| `{{define "…"}}` block names | Build-time diagnostic `theme_invalid` when a theme defines a block no built-in template has (existing behavior, unchanged) |
| CSS classes and variables | Documented contract only (this guide section); build never parses CSS |
