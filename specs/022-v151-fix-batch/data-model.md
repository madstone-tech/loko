# Data Model: v1.5.1 Patch Bug-Fix Batch

**Branch**: `022-v151-fix-batch` | **Date**: 2026-11-09

One entity changes home; every other surface this patch touches is fixed text or
prose. This document records the moved entity and the data it carries.

## Ownership manifest

The manifest records what the last successful build wrote to one output
directory. It is the single input to pruning.

| Field | Meaning | Example |
|---|---|---|
| Notice | Line 1 comment: `Code generated by loko from <sources>. DO NOT EDIT.` | sorted `*.loko.hcl` sources |
| Paths | One path per line, slash-separated, output-relative, sorted | `assets/style.css`, `diagrams/landscape.svg` |

**Location (since 1.5.1)**: `<parent(outDir)>/.<base>.loko/manifest`

- Default build (`--out dist`): `<project root>/.dist.loko/manifest`
- `loko build --out release`: `<project root>/.release.loko/manifest`
- The directory is created on first write with mode `0755`; the manifest file is
  written with mode `0644` (unchanged conventions from `Store.Commit`).

**Lifecycle / state transitions** (failure ordering spelled out in
[contracts/output-state.md](contracts/output-state.md) rules 1–6):

```
no state:                read → empty manifest → prune nothing
1.5.0 checkout upgrade:  read → legacy .loko-manifest → prune from it →
                         write .<base>.loko/manifest → remove legacy (all steps
                         of the build first having succeeded)
healthy 1.5.1:           read → .<base>.loko/manifest → prune → rewrite
corrupt/unreadable:      read → empty manifest → prune nothing (as in 1.5.0)
failed build:            artifacts written so far stay; legacy manifest stays
                         untouched; state manifest may be absent → next run
                         falls back and repairs
```

**Safety rules carried over unchanged** (from `vm.DecodeManifest`): comment lines,
blank lines, absolute paths, `..` segments, backslashes, drive letters and control
characters are dropped, so a corrupt manifest can only make the tool prune less.
Artifact paths that are unsafe (`vm.SafePath`) or equal the manifest name are
refused before any write (store.go:32-35).
