# Contract: Generated site output (021)

This is what `loko build --format html` and `loko serve` guarantee after 021. It adds to 014's
site contract, which still holds (one page per element and view, `index.html`, the generated-file
notice on line 2, byte-identical output).

## Files

| Path | Content |
|---|---|
| `index.html`, `view/*.html`, `<kind>/*.html` | pages (paths unchanged) |
| `assets/style.css`, `assets/custom.css`, `assets/site.js`, `assets/search-index.js` | as 014; contents changed |
| `assets/fonts.css` | **new**: notice, then one `@font-face` per bundled font (8 Latin-subset WOFF2, 500 KB or less before encoding) as base64 `data:` URIs; linked before `style.css`; not overridable |
| `assets/icons.css` | **new**: notice, then one rule per Lucide icon (the diagram's icon files, base64 `data:` URIs used as CSS masks); linked before `style.css`; not overridable |
| `assets/LICENSES.txt` | **new**: notice, then the OFL licence of each font family, Lucide's ISC licence and the brand notice, each unmodified under a heading |
| `assets/brand/madstone-eye.svg` | **new**: notice as an XML comment, then the Madstone Eye glyph |

Every file, including these, opens with the generated-file notice (014 FR-020).

No page or asset references `http:`, `https:` or `//`. The only exception is the "Generated by
loko" link in the footer, which is an ordinary anchor and is never fetched.

## Every page

- `<html>` has no `data-theme` in the file. The head script may set it at runtime.
- The sidebar contains, in order:
  - the Eye and `LOKO` wordmark
  - the project name and description
  - the search box (`#search`)
  - the Architecture tree (`nav.tree`, pruned per research R7)
  - the Views list
  - the footer note naming `*.loko.hcl`
- A breadcrumb `nav[aria-label="Breadcrumb"]` ends at the current page with `aria-current="page"`.
- The theme toggle is a `<button>` with `aria-pressed`. It is hidden when scripts are off.
- The menu button is shown only at narrow widths.
- At most one inline `<svg>` diagram, inside a `<figure>` with a `<figcaption>`.

## Element page

- The header holds:
  - the accent bar
  - `p.kind-label` (`COMPONENT · IN GATEWAY`)
  - `h1` with `span.icon-tile.kind-<kind>`
  - `p.meta` (technology · full id · `file:line`)
  - `p.lead` (the description)
- `main` holds the prose and a source note. When there is no prose, or `ProseInherited` is set, it
  holds the In context figure instead, plus a link to the parent's prose when inherited.
- `aside.rail` holds these sections, in order, omitting empty ones:
  `section.part-of`, `section.siblings`, `section.talks-to`, `section.in-context`.
  The In context section is omitted when its figure has moved into `main`.
- In the In context SVG, exactly one `g[data-loko-address]` has the class `loko-focus`.
- A system or container page also has `section.children` with one row per child, and its own view
  as an `<img>` figure with an "Open view" link.
- `nav.pager` holds previous and next links (`rel="prev"`/`rel="next"`) when they exist.

## View page

- The header label reads `<KIND> VIEW · <MODE>`. The metadata line gives the element and
  relationship counts.
- `figure.diagram` holds the inline SVG, the zoom controls (`button` reset, zoom in, zoom out) and
  links to `diagrams/<view>.svg` and `diagrams/<view>.d2`.
- `section.in-this-view` holds one row per element node. It is referenced by the SVG's
  `aria-describedby`.
- Dynamic views keep `table.steps` (019).

## Index

- `section.stats` holds four cards: systems, containers, relationships, diagnostics.
- The landscape figure has an "Open view" link.
- `section.systems` and `section.views` hold row lists.

## Behaviour (`site.js`, all optional; the page works without it)

| Input | Effect |
|---|---|
| `←` / `→` outside text fields | go to `rel=prev` / `rel=next` |
| theme toggle | switch light/dark; store in `localStorage["loko-theme"]` |
| tree `▸` | expand or collapse in place (collapsed nodes still link to their page) |
| wheel / click / drag / reset on a diagram | zoom / zoom 2× / pan / restore the `viewBox` |
| menu button | open or close the sidebar at narrow widths |
| search input | unchanged from 014 |

## Theme

- Light tokens apply by default. Dark tokens apply under `prefers-color-scheme: dark` unless
  `data-theme="light"` is set, or when `data-theme="dark"` is set.
- Print always uses the light tokens.
- The diagram panel is light in both themes.
